---
title: "Quickstart: add BEAM tools to a GitHub Actions workflow"
description: "Add setup-beam to a GitHub Actions workflow and install Erlang/OTP, Elixir, Gleam, or rebar3 with a single action step in under five minutes."
---

`setup-beam` integrates with GitHub Actions as a single workflow step. Once the step completes, all installed tools are on `PATH` and ready for your build commands. This guide walks through adding the action to an existing repository, choosing your versions, and running your test suite.

<Steps>
  <Step title="Create or open your workflow file">
    Create `.github/workflows/ci.yml` in your repository if it doesn't already exist. The file must start with a trigger and a `jobs` block:

    ```yaml
    on: push

    jobs:
      test:
        runs-on: ubuntu-24.04
        steps:
          - uses: actions/checkout@v4
    ```
  </Step>

  <Step title="Add the setup-beam step">
    Insert the `erlef/setup-beam@v1` step after `actions/checkout`. Use the `with:` block to specify which tools and versions to install:

    ```yaml
    - uses: erlef/setup-beam@v1
      with:
        otp-version: '27'
        elixir-version: '1.18'
    ```

    <Note>
      Always quote version values as YAML strings. `otp-version: 26.0` is parsed by YAML as the number `26`, which resolves differently from the string `'26.0'`. Use single or double quotes to be safe.
    </Note>
  </Step>

  <Step title="Run your tests">
    Add your build and test commands. The installed tools are on `PATH` immediately after the setup step:

    ```yaml
    - run: mix deps.get
    - run: mix test
    ```

    For Erlang projects use `rebar3 ct` or `rebar3 eunit`. For Gleam projects use `gleam test`.
  </Step>
</Steps>

## Complete workflow examples

Choose the example that matches your project's language and toolchain.

<CodeGroup>

```yaml Elixir on Ubuntu
# .github/workflows/ci.yml
on: push

jobs:
  test:
    runs-on: ubuntu-24.04
    name: OTP ${{matrix.otp}} / Elixir ${{matrix.elixir}}
    strategy:
      matrix:
        otp: ['25.3.2', '26.2.5', '27.3.3']
        elixir: ['1.17.3', '1.18.3']
    steps:
      - uses: actions/checkout@v4
      - uses: erlef/setup-beam@v1
        with:
          otp-version: ${{matrix.otp}}
          elixir-version: ${{matrix.elixir}}
      - run: mix deps.get
      - run: mix test
```

```yaml Erlang + rebar3 on Ubuntu
# .github/workflows/ci.yml
on: push

jobs:
  test:
    runs-on: ubuntu-24.04
    name: OTP ${{matrix.otp}} / rebar3 ${{matrix.rebar3}}
    strategy:
      matrix:
        otp: ['25.3.2', '26.2.5', '27.3.3']
        rebar3: ['3.23.0', '3.24.0']
    steps:
      - uses: actions/checkout@v4
      - uses: erlef/setup-beam@v1
        with:
          otp-version: ${{matrix.otp}}
          rebar3-version: ${{matrix.rebar3}}
      - run: rebar3 ct
```

```yaml Gleam on Ubuntu
# .github/workflows/ci.yml
on: push

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: erlef/setup-beam@v1
        with:
          otp-version: '27'
          gleam-version: '1.9.0'
      - run: gleam test
```

</CodeGroup>

<Tip>
  The Elixir and Erlang + rebar3 examples above use a `matrix` strategy to test multiple version combinations in the same workflow. Each combination runs as a separate job in parallel, giving you broad coverage without writing duplicate workflow files.
</Tip>

## Using action outputs

After the setup step runs, the exact resolved versions are available as step outputs. Reference them in later steps using `steps.<step-id>.outputs.<output-name>`:

```yaml
steps:
  - uses: actions/checkout@v4
  - uses: erlef/setup-beam@v1
    id: setup-beam
    with:
      otp-version: '27'
      elixir-version: '1.18'
  - run: echo "Installed OTP ${{ steps.setup-beam.outputs.otp-version }}"
  - run: echo "Installed Elixir ${{ steps.setup-beam.outputs.elixir-version }}"
```

The available outputs are:

| Output | Example value | Description |
|---|---|---|
| `otp-version` | `OTP-27.3.3` | Exact Erlang/OTP version installed |
| `elixir-version` | `v1.18.3-otp-27` | Exact Elixir version installed |
| `gleam-version` | `v1.9.0` | Exact Gleam version installed |
| `rebar3-version` | `3.24.0` | Exact rebar3 version installed |
| `setup-beam-version` | `7a27046` | Commit ID of the executed action version |

Outputs are only populated for tools that were actually installed. If you don't set `elixir-version`, the `elixir-version` output will be empty.
